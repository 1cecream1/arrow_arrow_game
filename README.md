# 一箭又一箭（Pygame 版）

参考微信小游戏《一箭又一箭》核心玩法实现的 Python 小游戏。
所有代码、关卡、美术（程序绘制）均为本项目原创，未使用原游戏素材。

## 运行方法

```bash
pip install pygame      # 只依赖 pygame
python main.py
```

Windows 下也可以直接双击 `启动游戏.bat`。

## 玩法规则

- 棋盘上有上、下、左、右四个方向的单格箭头；
- 用鼠标点击一个箭头：如果它前进方向到棋盘边界之间**没有**其他箭头，
  它就沿该方向加速飞出棋盘并消失；
- 如果路径上**有**其他箭头挡路：箭头不能消除，会**晃动 + 变红**，
  挡路者同时闪红，并弹出“撞上了！”提示，同时扣 1 次失误机会；
- 清空本关全部箭头 → 显示通关结果并进入下一关；
  失误次数（爱心）耗尽 → 显示失败结果，可重新开始本关；
- 鼠标悬停在某支箭头上时，会显示它的前进光路（绿 = 通，红 = 被挡），方便理解判定。

## 功能对照（作业要求 → 实现位置）

| 作业要求 | 实现位置 |
| --- | --- |
| 图形化界面、鼠标点击 | `main.py`（Pygame） |
| 上/下/左/右箭头 | `levels.py`（ASCII 关卡），`game_core.Arrow` |
| 路径判断（同行/列到边界） | `game_core.Board.scan()` |
| 无阻挡飞出并消失（动画） | `main.py` `ArrowView`（加速飞行 + 涟漪 + “飞出！”） |
| 有阻挡的碰撞反馈（动画） | 晃动 `shake_t`、闪红 `flash_t`、挡路者闪红、漂浮文字 |
| 失误次数与剩余显示 | `game_core.Board.mistakes_left`，界面用爱心表示 |
| ≥3 个可通关关卡 | `levels.py` 共 **5 关**，全部经求解器验证 |
| 通关/失败结果显示与进入下一关 | 通关弹窗 / 失败弹窗 / 全部通关界面 |
| 重新开始 | “重新开始”按钮 + 快捷键 R，恢复初始状态 |
| 开始 / 游戏 / 结算三种界面 | 菜单、对局、通关/失败/全通关 |

## 代码结构

```
main.py               图形界面 + 主循环（Pygame）
game_core.py          核心规则：棋盘、箭头、路径判断、失误判定、求解器
levels.py             5 个关卡数据（ASCII 书写，注释含验证信息）
tools/gen_levels.py   开发期：随机生成关卡并用 DFS 求解器验证可通关后写出 levels.py
tools/verify_levels.py 复核脚本：验证每关存在通关顺序并打印一条解法
tools/autoplay_test.py 自动试玩回归测试：不开窗口，模拟真实点击走完全流程
screenshots/          自动试玩沿途截图（菜单、碰撞、飞行、每关起止、失败、全通关）
```

## 关卡可通关性验证

- `game_core.solve_level()` 用「DFS + 记忆化」在剩余箭头集合的状态空间上搜索，
  求出一条通关顺序；
- `tools/gen_levels.py` 随机撒箭头后调用求解器，只保留「可解且开局至少有若干
  被挡箭头」的布局作为正式关卡，难度按棋盘大小 / 箭头数量 / 开局阻挡数递进；
- `tools/verify_levels.py` 可随时复核；
- `tools/autoplay_test.py` 用求解顺序通过 `Game.on_click()` 走**真实点击路径**
  把 5 关全部通关，并断言：碰撞扣失误、被挡箭头不消失、重新开始复原、
  失误耗尽进失败界面、清空进下一关等（当前 36 项断言全部通过）。

一个求解时发现的有趣性质：箭头减少只会解除阻挡、不会新增阻挡，
所以“每次都点当前能飞的箭头”一定能通关，不存在点错顺序导致的死局；
关卡难度来自“找出哪些箭头能飞”。

## AIGC / Coding Agent 使用说明

本项目在开发过程中使用 AI 编程助手（WorkBuddy / Coding Agent）辅助：

理解各模块职责与判定逻辑，并保证程序可运行。
