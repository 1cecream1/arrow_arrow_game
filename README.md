# 一箭又一箭（Pygame 版）

参考微信小游戏《一箭又一箭》核心玩法实现的 Python 小游戏。
玩法规则、关卡生成与全部代码均为本项目原创，未使用原游戏的素材或代码；
图形素材由 AI 生图生成后自行处理，音效用 Python 现场合成（见下文「AIGC / 自制素材」）。

## 运行方法

```bash
pip install pygame      # 只依赖 pygame
python main.py                     # 默认进入菜单：开始游戏 / 更多关卡
python main.py --level 3           # 直接从第 3 关开始
python main.py --random            # 随机布局：每次开局现场生成 5 关
python main.py --random --seed 20260919   # 指定种子，复现同一批关卡
```

Windows 下也可以直接双击 `启动游戏.bat`。

## 界面与流程

```
菜单 ─┬─ 开始游戏 ──> 固定 5 关（第 1 关起，逐关推进）
      └─ 更多关卡 ──> 关卡选项 ─┬─ 点任意关卡卡片 ──> 直接挑战该关
                                └─ 随机挑战 ──> 现场生成 5 关（布局每局不同）

对局 ──> 清空箭头 ──> 通关结算（星级 + 得分） ──> 下一关 / 关卡选项
      └─ 失误用完 ──> 失败结算 ──> 重新挑战 / 关卡选项
```

- **菜单**：和游戏内同款的圆角卡片布局。左侧「玩法」卡片，右侧「自动演示」卡片里有一个
  4×4 小棋盘**自动试玩**（每次挑一个当前能飞的箭头飞出，清空后自动换一局），
  不用读文字也能看懂玩法。
- **关卡选项（更多关卡）**：5 张同尺寸卡片，每张显示 棋盘大小 / 箭头数 / 失误上限 /
  目标用时 / **历史最佳星级与最高分**，鼠标悬停高亮，点一下直接开始那一关。
- **对局界面**：顶部 HUD 依次是 关卡名、剩余箭头、**本局得分**、剩余失误（爱心图片）、
  本局模式与种子、**用时 / 目标用时**（超时会变红）；底部「重新开始 / 提示一下 / 返回菜单」。
- **结算界面**：通关弹窗显示 **1~3 颗星（逐颗弹出动画）+ 本关用时 / 目标用时 / 失误 / 得分 /
  本局累计分**；失败弹窗说明剩余箭头数。全部通关界面显示本局总分与经典关卡累计星数。

## 计分与星级（`game_core.evaluate`）

- 目标用时 `par = 6 秒 + 1.8 秒 × 箭头数`（第 1 关 15s → 第 5 关 33s）；
- 得分 = 1000 − 200 × 失误次数 − 最多 250 × 超时比例，保底 100 分；
- 星级：**3 星** = 零失误且不超目标用时；**2 星** = 失误 ≤1 且用时 ≤ 1.6 倍目标；**1 星** = 通关；
- 经典关卡每个关卡的最高分与星级存进 `records.json`（随机关卡布局每局不同，不记录）。

## 音效（`sound.py` + `tools/make_sounds.py`）

| 事件 | 音效 | 合成方式 |
| --- | --- | --- |
| 正确选择（箭头飞出） | 掌声 | 20 多次随机时刻的短噪声爆发（多个“巴掌”）+ 人群底噪 + 早期反射，再走一阶高通 |
| 错误选择（被挡住） | 失败音效 | 420Hz→110Hz 下行方波（带颤音）+ 少量噪声，指数衰减 |
| 本关通关 | 烟花 | 引信咻声 → 低频爆响 → 90 多个噼啪细碎爆裂，共两次爆炸 |
| 全部通关 | 上行琶音 | C5-E5-G5-C6 三角波琶音 + 高频闪光 |

全部用 Python 标准库（`wave`/`array`/`math`/`random`）现场合成，**不下载第三方音频**，
避免版权问题；音量做了统一平衡，播放失败（没有声卡/缺素材）自动静默降级，
`M` 键随时静音。

## AIGC / 自制素材

**图片**（AI 生图 → 自写脚本处理）：

| 原始需求 | 处理（`tools/prepare_assets.py`） |
| --- | --- |
| 箭头 / 爱心是纯白底、无透明通道，直接贴会带白方块 | 从**四周边界洪水填充**，只把与边界连通的白色判为背景 —— 若简单地把所有近白像素设透明，箭头内部高光会被打穿成洞；再对蒙版高斯模糊做羽化 |
| 底纹图带「AI生成」水印、自带细网格会和棋盘格子线打架 | 裁掉水印区域，再「缩小到 96px → 放大到 720px」柔化细网格，作为界面背景底纹 |

处理结果：`assets/arrow.png`、`assets/heart.png`、`assets/board_bg.png`；
原始 AI 输出归档在 `assets/raw/`（游戏不读取，仅供溯源）。
箭头原图朝右，按 `sprites.py` 的 `ROTATE` 表旋转出四个方向，用
`tools/check_sprites.py` 渲染对照图逐一人眼确认（避免“方向画反”）。

**音效**（自行合成，见上表）：`assets/sounds/*.wav`，由 `tools/make_sounds.py` 生成。

**性能**：箭头按 `(方向, 像素尺寸)` 缓存「旋转 + 缩放」，碰撞用的红色版本预生成
（灰度 → 染红 → 提亮，**不能**用蓝色直接乘红色，那会压成近黑），每帧只做 blit；
菜单与关卡选项把不动的部分预渲染成一张离屏图，每帧只 blit 一次。
素材缺失时自动退回程序绘制的箭头/爱心，游戏仍可运行。

```

sprites.py              AIGC 图片素材的加载、旋转缩放、变色与缓存（含程序绘制兜底）

tools/gen_levels.py     生成固定关卡并写出 levels.py（复用 game_core 的生成器）
tools/verify_levels.py  复核固定关卡每关存在通关顺序并打印一条解法
tools/autoplay_test.py  自动试玩回归测试：计分/星级/音效/关卡选项/记录/两种模式的完整流程
tools/perf_check.py     帧率实测
screenshots/            自动试玩沿途截图 + 素材自检图
提交说明.md             git 提交拆分顺序、忽略规则与自测命令
.gitignore              忽略 __pycache__ / records.json / .workbuddy 等
records.json            本地最高分存档（首次通关后生成，已在 .gitignore 中）
```

## 关卡可通关性验证

- `game_core.solve_state()` 用「DFS + 记忆化」在剩余箭头集合的状态空间上搜索，求出一条通关顺序；
  `game_core.make_random_level()` 只接受求解器判定「可解、且开局至少有若干支箭头被挡」的布局；
- `tools/verify_levels.py` 复核固定关卡，`tools/gen_levels.py` 重新生成固定关卡；
- `tools/autoplay_test.py` 用求解顺序通过 `Game.on_click()` 走**真实点击路径**：
  计分与星级的边界条件（3/2/1 星、保底分、par 分界）、音效接线（点对=鼓掌、点错=失败、
  通关=烟花、静音后不出声）、关卡选项（菜单→关卡选项→点卡片进对应关→返回菜单→随机挑战）、
  成绩记录（写入、只被更高分覆盖、失败不计分）、经典 5 关连打、随机 6 局 × 5 关自动通关。
  当前 **100 项断言全部通过**。

求解器发现的游戏性质：箭头减少只会解除阻挡、不会新增阻挡，所以“每次都点当前能飞的箭头”
一定能通关，不存在点错顺序导致的死局；难度来自“找出哪些箭头能飞”。
正因为这条性质，随机关卡只要被求解器判定为可解，玩家就一定能通关——随机生成是安全的；
菜单里的自动演示也是靠它，随便挑一个可飞的箭头演示都不会演示到死局。

## 性能实测（`python tools/perf_check.py`）

| 场景 | 平均单帧 | 结论 |
| --- | --- | --- |
| 菜单（自动演示在动） | 0.21 ms | 静态层预渲染 |
| 关卡选项（5 张卡片） | 0.15 ms | 静态层预渲染（成绩变化时才重建） |
| 对局（6×6 / 15 支箭头） | 2.60 ms | 60 FPS 预算 16.7 ms，余量约 6 倍 |
| 连续飞出动画 | 3.24 ms | 同上 |

注：该数据是 dummy 驱动下的纯软件渲染，真机由显卡合成只会更快。

## AIGC / Coding Agent 使用说明

本项目在开发过程中使用 AI 编程助手（WorkBuddy / Coding Agent）辅助：

- 代码框架、界面与自动化脚本由 AI 生成；图片素材由 AI 生图生成后，再用自写脚本
  做白底抠图、裁水印等处理；音效由自写脚本用标准库合成；
- 关卡由 AI 编写的「生成器 + 求解器」自动生成并逐关验证可通关；
- 测试由 AI 编写的自动试玩脚本完成（100 项断言）。

提交者已逐行阅读、运行并修改过全部代码，理解各模块职责与判定逻辑，并保证程序可运行。
开发过程中被定位并修复的典型问题：
① 行列坐标 (r, c) 与屏幕坐标 (x, y) 混用导致箭头方向整体画反；
② 图片素材直接相乘“染红”会把蓝色箭头压成近黑，改为灰度后染红；
③ 菜单逐帧重绘大量文字导致帧耗时升高，改为静态层预渲染；
④ 关卡选项界面忘了清屏导致菜单残影叠在卡片上；
⑤ 错误音效一开始用高通滤波，把下行基频滤掉、听不出“往下掉”。
